# 사맛디 협업 대시보드·타임라인 디자인 개선 플랜

작성일: 2026년 11월 14일. 상태: **구현 중** (DESIGN-01부터 단계별 PR).

조사 기준은 `codex/review-05-version-tasks`의 `398fc2cda47313a13d76056b792d93932dc4e6e2`와 이전 PR의 실행 화면 캡처다. 구현 착수 전에 main과 REVIEW-05의 병합 상태를 다시 확인한다.

**음원의 특정 구간에 남긴 피드백이 담당자의 할 일이 되고, 그 할 일이 내 대시보드·팀 칸반·타임라인에서 같은 카드로 보이게 만든다.** 리뷰 화면은 Frame.io의 미디어 옆 대화 흐름을, 작업 화면은 GitHub Projects의 "같은 항목을 여러 보기로"(표·보드·로드맵)와 Trello의 카드 보드·타임라인을 참고한다.

[UI 수정 플랜](web-ui-redesign-plan.md)과 [음원 리뷰 UX 개선 플랜](audio-review-ux-plan.md)의 후속 작업이다. 두 문서에서 정한 탐색 구조, URL, 리뷰 조작 규칙은 유지한다. 이 문서는 시각 체계, 작업 보기, 피드백과 할 일의 연결을 다룬다.

## 3. 화면 구조

전역 메뉴는 `사맛디 · 내 대시보드 · 프로젝트 | 알림 · 계정`으로 정리한다. `/work` 경로는 유지하고 이름만 `내 대시보드`로 바꾼다. 프로젝트 탭 `음원 · 작업 · 활동 · 설정`은 유지한다. **프로젝트의 작업 탭을 협업 대시보드로 삼고, 기본 보기를 목록에서 보드로 바꾼다.**

| 화면 | 첫 화면에서 답할 질문 | 기본 보기 |
| --- | --- | --- |
| 내 대시보드 `/work` | 오늘 내가 할 일과 나를 기다리는 검토·답변은 무엇인가? | 시간별로 묶은 내 작업 + 기다리는 항목 |
| 협업 대시보드 `/projects/:id/tasks` | 이 곡에서 누가 무엇을 하고, 무엇이 검토를 기다리는가? | 요약 줄 + 칸반 |
| 타임라인 `/projects/:id/tasks?view=timeline` | 언제 무엇이 겹치고, 마감까지 무엇이 남았는가? | 담당자별 막대 |
| 음원 리뷰 | 어느 구간에 어떤 의견이 있고, 그중 무엇이 할 일이 됐는가? | 파형 + 피드백 패널 |

모든 보기에서 작업 카드는 같은 정보 순서를 사용한다.

```text
┌──────────────────────────────────────┐
│ 후렴 보컬 2dB 낮추기                    │  제목
│ ♪ 메인 믹스 · mix-03.wav · 0:42–0:47   │  원본 음원·버전·구간. 누르면 그 피드백에서 리뷰를 연다
│ (민) 11/20 · D-3          피드백 2      │  담당자 아바타 · 마감 · 연결 피드백 수
└──────────────────────────────────────┘
```

카드를 누르면 오른쪽 상세 패널이 열리고 URL은 `/projects/:id/tasks/:taskId`로 바뀐다. 보드·목록·타임라인의 스크롤과 필터는 유지한다. 800px 이하에서는 상세를 전체 화면으로 연다.

### 협업 대시보드 (칸반)

```text
작업   [보드] [목록] [타임라인]    검색   담당자 ▾  마감 ▾  묶기: 없음 ▾      [새 작업]
──────────────────────────────────────────────────────────────────────────────
할 일 4 · 진행 중 2 · 검토 요청 1 · 완료 6      (민) 3  (지) 2  (서) 2      지연 1
──────────────────────────────────────────────────────────────────────────────
● 할 일  4        ● 진행 중  2       ● 검토 요청  1      ● 완료  6
┌────────────┐   ┌────────────┐    ┌────────────┐     ┌────────────┐
│ 카드         │   │ 카드         │    │ 카드         │     │ 카드         │
└────────────┘   └────────────┘    └────────────┘     └────────────┘
+ 할 일 추가       + 추가
```

- 요약 줄은 기존 `task-counts` 집계로 상태별 개수를, 팀원 아바타로 담당 개수를 보여준다. 아바타를 누르면 담당자 필터가 적용된다.
- 열 머리글에 상태 색 점·이름·개수를 표시한다. `할 일`과 `진행 중` 열 아래에서 제목만 입력해 바로 추가한다. `검토 요청`·`완료`는 추가 입력이 필요해 빠른 추가를 두지 않는다.
- 드래그로 열 이동과 같은 열의 순서 변경을 모두 지원한다. 두 동작은 기존 상태·`position` 저장 경로와 revision 검사를 사용한다. `검토 요청`으로 옮기면 결과 버전·검토 설명 입력을 받은 뒤 확정한다.
- 카드 메뉴의 `상태 이동`·`위로`·`아래로`를 드래그의 키보드 대안으로 유지한다.
- `묶기: 담당자`를 고르면 담당자별 가로 줄로 나눈다. `완료` 열은 최근 항목부터 보여주고 나머지는 더 보기로 연다.

### 타임라인

```text
작업   [보드] [목록] [타임라인]     [주 | 월]   묶기: 담당자 ▾        ◀  오늘  ▶
             11/12 수   11/13 목   11/14 금 │ 11/15 토   11/16 일   11/17 월
                                       오늘 │                 ▼ mix-03 업로드
(민)       [███ 보컬 튠 수정 ███]            │
           [██████ 후렴 보컬 2dB 낮추기 ███████████████]
(지)                                        ◆ 믹스 확인 (마감만)
미할당               [██ 인트로 리버브 ██]
──────────────────────────────────────────────────────────────────────────
날짜 없음 3   [인트로 레벨]  [베이스 EQ]  [엔딩 페이드]       ← 끌어다 놓으면 일정 지정
```

- 막대 색은 상태를 따른다. 마감이 지난 미완료 작업은 빨간 테두리와 `지연` 문구로 표시한다.
- 마감일만 있으면 마름모 표식, 시작일만 있으면 오늘까지 점선 막대로 그린다. 날짜가 없는 작업은 아래 영역에 모아 두고 끌어다 놓아 일정을 정한다.
- 막대를 옮기거나 양 끝을 끌어 `start_on`·`due_on`을 바꾼다. 상세 패널의 날짜 입력과 같은 저장 경로를 사용하고, 실패하면 원래 위치로 되돌리고 이유를 표시한다.
- 기간 안에 재생 준비가 끝난 버전을 세로 표식으로 표시해 달력 시간과 음원 버전을 연결한다. 곡 안의 위치(0:42)는 카드의 원본 구간 칩에만 표시하고 타임라인 축으로 쓰지 않는다. 전략 문서의 "오디오 시간과 달력 시간을 같은 축으로 다루지 않는다"는 원칙을 따른다.
- 주·월 단위와 `오늘` 이동을 제공한다. 날짜 경계는 기존 마감일 규칙과 같은 `Asia/Seoul`을 사용한다.
- 800px 이하에서는 막대 대신 주 단위 일정 목록으로 보여준다.
- 의존 관계와 자동 일정 계산은 이번 범위에 넣지 않는다.

### 내 대시보드

```text
내 대시보드                                           [목록] [보드] [타임라인]
담당 7    지연 1    7일 내 3    검토 대기 2
───────────────────────────────────────────────┬──────────────────────────────
지연      후렴 보컬 2dB 낮추기                    │ 나를 기다리는 것
          새벽 EP · 메인 믹스 0:42–0:47 ▶   11/12 │ 검토 요청 · 인트로 레벨 (지)
오늘      보컬 튠 수정  ...                        │ 새 답글 · 0:42 "확인했어요"
이번 주   ...                                     │ 새 피드백 3 · mix-03.wav
나중      ...                                     │
날짜 없음 ...                                     │ 최근 음원
                                                │ 메인 믹스 · mix-03 · 2시간 전
```

- 내 담당 작업을 `지연 · 오늘 · 이번 주 · 나중 · 날짜 없음`으로 묶는다. 카드에 프로젝트 이름을 함께 표시한다.
- `보드`·`타임라인` 보기는 협업 대시보드의 컴포넌트를 재사용하고, 여러 프로젝트의 내 작업을 보여준다.
- 오른쪽 `나를 기다리는 것`에는 검토 요청, 내 피드백에 달린 답글, 내가 올린 버전에 달린 새 피드백을 모은다. 알림과 같은 대상 링크를 사용한다.
- 상단 개수는 기존 대시보드 집계를 사용하며, 개수를 누르면 해당 필터로 목록을 연다.

### 음원 리뷰와 할 일 연결

```text
피드백 작성 · 0:42.300–0:47.100 구간
┌──────────────────────────────────────────┐
│ 후렴 들어갈 때 보컬이 2dB 정도 커요          │
└──────────────────────────────────────────┘
[✓] 할 일로 만들기    담당 (민) ▾    마감 11/20 ▾
                                        [피드백 남기기  ⌘↵]
```

- 작업 생성 권한이 있는 소유자·편집자에게 `할 일로 만들기`를 보여준다. 선택하면 피드백, 작업, 연결, 활동, 담당자 알림을 한 번에 저장한다. 작업 제목은 본문 첫 줄로 시작하고 이후 상세에서 수정한다.
- 선택하지 않으면 지금처럼 피드백만 저장한다. 대화 안의 `작업 만들기`도 유지한다.
- 파형 마커는 작성자 아바타로 표시한다. 연결된 작업이 있으면 작업 상태 색의 작은 점을 붙이고, 해결된 피드백은 흐리게 표시한다. 구간 피드백은 파형 위의 띠로 범위를 보여준다.
- 피드백 카드는 `아바타 · 이름 · 시점 칩 · 본문 · 작업 칩` 순서로 표시한다. 작업 칩 `● 진행 중 · 민 · 11/20`을 누르면 작업 상세 패널을 연다.
- 작업 카드의 원본 구간 칩은 해당 버전·피드백·위치의 리뷰 링크를 연다. 리뷰 화면에서 REVIEW-03의 `구간 듣기`로 그 구간을 다시 듣는다. 다른 화면에서 자동 재생하지 않는 이유는 브라우저의 자동 재생 제한과 기존 "자동 재생하지 않는다" 원칙 때문이다.

## 4. 시각 체계

- 밝은 GitHub형 기본 화면과 녹색 강조색을 유지한다. 리뷰 화면만 어둡게 하는 Frame.io형 배치는 8절의 결정 항목으로 둔다.
- `:root` 토큰을 중립 단계, 상태 색, 위험·주의 색, 그림자·반경으로 확장한다. 상태 색의 초기 시안은 할 일 회색, 진행 중 파랑, 검토 요청 주황, 완료 녹색, 지연 빨강이다. 색만으로 상태를 전달하지 않고 이름·아이콘을 함께 표시하며, 글자 대비는 4.5:1 이상을 확인한다.
- 아바타는 표시 이름의 첫 글자와 계정 ID로 정한 8색 팔레트 중 하나를 사용한다. 이미지 업로드는 하지 않는다. 화면 낭독기에는 이름을 읽힌다.
- 공통 컴포넌트로 `Avatar`, `StatusChip`, `DueChip`(`오늘`, `D-3`, `2일 지연`), `SourceChip`(음원·버전·구간), `Menu`(버튼 + 팝오버), `ViewSwitcher`, `SidePanel`을 만든다. 알림·계정·프로젝트 전환·카드 관리의 `<details>`를 `Menu`로 바꾼다.
- 아이콘은 한 파일의 작은 인라인 SVG로 관리한다. 보드·타임라인·드래그를 위한 외부 라이브러리는 도입하지 않고, 이전 계획처럼 기존 Next.js·CSS로 구현한다.
- Geist와 Noto Sans KR을 유지하고 시간·날짜·개수에는 고정폭 숫자를 사용한다. 터치 대상은 44px 기준을 유지한다.
- 다크 테마는 이번 범위에 넣지 않는다. 토큰은 나중에 다크 값을 추가할 수 있는 구조로 정의한다.

## 5. 데이터와 API 변경

계약을 바꾸는 PR에서 OpenAPI와 `pnpm generate:api` 결과를 함께 갱신한다. 기존 응답 필드는 유지하고 필요한 필드를 추가한다. 카드마다 별도 요청을 보내 요약 정보를 모으지 않는다.

| 변경 | 내용 | 단계 |
| --- | --- | --- |
| 표시 이름 | `accounts.display_name text NULL`. 로그인 시 OIDC `name` 클레임이 있으면 채우고 계정 메뉴에서 수정한다. Session·Member·Note·Reply 응답에 `name`을 추가하고, 비어 있으면 화면에서 이메일 앞부분을 사용한다. | DESIGN-01 |
| 카드 요약 | Task 응답에 `created_at`, `updated_at`, 첫 연결 피드백의 `source`(음원 ID·제목, 버전 ID·파일명, 시작·끝 밀리초)를 추가한다. | DESIGN-02 |
| 같은 열 순서 | 기존 `position` 저장 경로로 드래그 순서를 바꾼다. 열 이동과 같은 revision 충돌 처리를 적용한다. | DESIGN-02 |
| 피드백과 할 일 동시 생성 | 노트 생성 요청에 선택 필드 `task: { assignee_id?, due_on? }`를 추가한다. 같은 트랜잭션에서 노트·작업·연결·활동·알림을 기록하고, 하나라도 실패하면 모두 저장하지 않는다. 작업 생성 권한 규칙을 그대로 적용한다. | DESIGN-03 |
| 시작일 | `web_tasks.start_on date NULL`과 `CHECK (start_on IS NULL OR due_on IS NULL OR start_on <= due_on)`. TaskEditor·상세에 입력을 추가하고 날짜 변경을 활동에 기록한다. | DESIGN-04 |
| 기간 조회 | `GET /v1/projects/:project/tasks?from=&to=`로 기간과 겹치는 작업을, `scheduled=false`로 날짜 없는 작업을 조회한다. 기존 필터·커서와 조합한다. | DESIGN-04 |
| 버전 표식 | 기간 안의 `ready` 버전(음원 제목·파일명·시각)을 조회한다. 활동 API의 `version.ready`로 충분한지 먼저 확인하고 부족할 때만 조회를 추가한다. | DESIGN-04 |
| 내 대시보드 | DashboardTask에 `start_on`, `source`, 담당자, 피드백 수를 추가한다. `waiting` 조회로 검토 요청, 내 피드백의 새 답글, 내가 올린 버전의 새 피드백을 모은다. | DESIGN-05 |

## 6. PR 구현 순서

`DESIGN-*`는 이번 계획의 작업 ID다. 브랜치는 `codex/design-01-foundation` 형태를 사용하고, 후속 PR은 바로 앞 단계 브랜치를 base로 둔다.

| 순서 | 범위 | 완료 조건 |
| --- | --- | --- |
| DESIGN-01 · 디자인 기반 | 토큰, Avatar·StatusChip·DueChip·Menu·아이콘, 전역 메뉴·프로젝트 전환 교체, 표시 이름 | 기존 모든 화면의 AS-IS·TO-BE 캡처. 기존 `verify:pilot` 통과. 색 없이도 상태 구분. 390·800·1440px 확인 |
| DESIGN-02 · 칸반 협업 대시보드 | 작업 탭 기본 보드, 요약 줄, 열 머리글·빠른 추가, 새 카드, 같은 열 순서 드래그, 담당자 묶기, 상세 패널 | 드래그와 키보드 메뉴의 결과가 같음. 검토 요청 이동 시 입력 요구 유지. 101개 이상 작업에서 필터와 개수 일치. 동시 수정 충돌 처리 |
| DESIGN-03 · 피드백에서 할 일로 | 작성창의 할 일 선택, 원자적 생성 API, 아바타·상태 마커, 대화의 작업 칩, 카드의 원본 구간 칩 재생 | 구간 피드백 한 번 저장으로 작업·연결·알림 생성. 실패 시 아무것도 남지 않음. 검토자에게 선택 미노출. 카드 칩에서 원본 피드백·구간으로 이동 |
| DESIGN-04 · 타임라인 | `start_on` 마이그레이션, 기간 조회, 주·월 보기, 오늘선, 묶기, 날짜 없음 영역, 막대 이동·길이 조절, 버전 표식, 모바일 일정 목록 | 막대 드래그와 날짜 입력이 같은 저장 경로 사용. 시작일이 마감일보다 늦으면 거절. `Asia/Seoul` 날짜 경계. 키보드로 날짜 변경 |
| DESIGN-05 · 내 대시보드 | 시간별 묶음, 나를 기다리는 것, 최근 음원, 보드·타임라인 보기 재사용 | 개수와 목록이 일치. 여러 프로젝트 카드에 프로젝트 이름 표시. 모든 항목이 정확한 대상으로 이동 |
| DESIGN-06 · 통합 검증 | 두 계정 시나리오, 접근성·반응형 점검, 검증 기록 | 7절의 기준 실행과 기록 |

공통 컴포넌트를 먼저 만들어야 이후 화면이 같은 모양을 쓰므로 DESIGN-01을 첫 단계로 둔다. 타임라인은 칸반의 카드와 상세 패널을 재사용하므로 DESIGN-02 뒤에 둔다. 피드백과 할 일의 연결을 먼저 검증하려면 DESIGN-03을 DESIGN-02보다 앞당길 수 있다. DESIGN-03 직후 1차 사용성 확인을 한다.

각 PR에는 같은 테스트 음원·계정의 AS-IS·TO-BE 캡처, 재현 경로, 실행한 검사 결과를 남긴다. 계획의 완료 조건을 실행 결과처럼 기록하지 않는다.

## 7. 수용 기준과 검증

### 두 계정 시나리오

1. 소유자 A가 `메인 믹스`에 `mix-01.wav`를 올린다.
2. 편집자 B가 0:42–0:47 구간에 피드백을 남기면서 `할 일로 만들기 · 담당 A · 마감 11/20`을 선택한다.
3. A의 알림과 내 대시보드 `이번 주`에 카드가 생긴다. 원본 구간 칩을 누르면 그 피드백이 선택된 리뷰 화면이 열린다.
4. 협업 대시보드 보드에서 카드를 `진행 중`으로 옮기고, 타임라인에서 시작일을 정한다.
5. A가 `mix-02.wav`를 올리고 카드를 `검토 요청`으로 옮기며 결과 버전을 지정한다. 타임라인에 업로드 표식이 보인다.
6. B의 내 대시보드 `나를 기다리는 것`에 검토 요청이 보인다. B가 v1 피드백과 v2를 들어본 뒤 작업을 완료한다.

### 기능·접근성 회귀

- 보드 드래그, 타임라인 막대 조작에 키보드·터치 대안이 있고 같은 결과를 저장한다. 포커스가 보이고 대화상자·패널을 닫으면 원래 카드로 돌아온다.
- 타임라인 막대는 화면 낭독기에 `후렴 보컬 2dB 낮추기, 담당 A, 11월 14일부터 20일, 진행 중`처럼 읽힌다.
- 390px에서 페이지 전체의 가로 스크롤이 없다. 보드의 가로 스크롤은 보드 영역 안에서 처리하고, 타임라인은 일정 목록으로 바뀐다.
- 로딩, 빈 상태, 필터 결과 없음, 날짜 없는 작업만 있는 경우, 권한 없음, 네트워크 실패, revision 충돌을 각 보기에서 확인한다.
- `apps/web`에서 `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm verify:pilot`을 실행한다. API 변경 PR은 격리 DB의 `ops/verify-web.sh`와 해당 Go 검사를 포함한다. Chrome·Firefox와 모바일 크기 WebKit에서 검증하고 에뮬레이션을 실기기 검증으로 기록하지 않는다.

# 사맛디 웹 UI 수정 플랜

작성일은 2026년 11월 12일이다. 조사 기준은 Samtdi `d338ef5bf9eec40908ad889f6494592a9ef2ee48`과 로컬 실행 화면이다. 아래 계획으로 UI-01~UI-06을 구현했다. PR과 확인한 동작은 문서 끝에서 확인할 수 있다.

2026년 11월 13일 후속 [음원 리뷰 UX 개선 플랜](audio-review-ux-plan.md)을 작성했다. 해당 문서는 Samply·Frame.io를 참고한 음원 리뷰 개편의 구현 범위와 검증 기록을 다룬다.

**프로젝트를 고르고, 음원을 듣고, 피드백을 작업으로 연결하는 순서가 화면에서 보이게 만든다.** GitHub의 프로젝트별 탐색, 목록에서 상세로 들어가는 구조, 같은 작업을 여러 보기로 확인하는 방식을 적용한다. 기본 프로젝트 화면은 음원 목록으로 정한다. [GitHub 저장소 안내](https://docs.github.com/en/repositories) · [GitHub Projects 안내](https://docs.github.com/en/issues/planning-and-tracking-with-projects/learning-about-projects/about-projects)

이 문서는 화면별 구현 범위, 사용자 동작, PR 순서와 완료 조건을 관리한다. 설계 판단과 이유 표, Mermaid 구조도는 [사맛디 Notion](https://app.notion.com/41673b56612a814884cdef5a60bd96d8)에 기록한다. 기존 [MVP 구현 계획](web-implementation-plan.md)과 [MVP PR 계획](web-pr-plan.md)에 이어지는 UI 개선 작업이다.

## 1. 현재 화면에서 확인한 문제

- 프로젝트 페이지에 개인 할 일, 음원 생성·업로드, 재생기, 노트, 작업 보드, 활동, 반출, 팀원 관리가 동시에 렌더링된다. 프로젝트 제목 위에도 다른 프로젝트의 할 일이 표시된다. [현재 화면 조립](../apps/web/app/workspace.tsx)
- 듣기 전에 음원 이름 입력, 음원 선택, 업로드 폼과 버전 선택을 지나야 한다. 현재 곡과 버전의 정보가 여러 컨트롤에 흩어져 있다. [음원 화면](../apps/web/app/media-library.tsx)
- 각 카드의 `카드 편집`과 `상태·보관 설정`이 같은 편집 폼을 연다. 새 작업 폼부터 상태, 검토 설명, 결과 버전이 함께 나타난다. [작업 보드](../apps/web/app/task-board.tsx)
- 기본 오디오 컨트롤과 별도 재생 위치 슬라이더가 함께 보인다. 각 피드백에 답글 입력창이 열린 상태로 나열된다. [플레이어](../apps/web/app/version-review.tsx) · [노트](../apps/web/app/version-notes.tsx)
- 사이드바에서 다른 프로젝트를 눌러도 URL이 바뀌지 않는 것을 Chrome에서 확인했다. 내 작업과 배정 알림의 링크는 해당 작업의 상세 대신 보드 위치를 가리킨다. [프로젝트 선택](../apps/web/app/workspace.tsx) · [내 작업](../apps/web/app/workspace-activity.tsx) · [알림](../apps/web/app/notifications.tsx)
- 390×844 화면에서는 프로젝트 목록과 생성 폼이 본문 앞을 크게 차지하고 가로 잘림도 관찰됐다. [현재 스타일](../apps/web/app/styles.css)

## 2. 화면과 탐색 구조

전역 헤더에는 사맛디 홈, `프로젝트`, `내 작업`, 알림, 계정 메뉴를 둔다. 프로젝트 안에서는 프로젝트 선택기와 현재 이름, `음원 · 작업 · 활동 · 설정` 탭을 항상 같은 위치에 둔다. 로그인 후 기본 진입은 프로젝트 목록이며, 초대·알림·공유 링크로 왔으면 해당 대상으로 돌아간다.

| 화면 | 들어오는 곳과 목적 | 기본으로 보이는 정보 | 주요 행동 | 다음 상태와 완료 조건 |
| --- | --- | --- | --- | --- |
| 프로젝트 목록 | 로그인·로고에서 진입해 작업할 프로젝트 선택 | 검색, 프로젝트 이름과 내 역할, 최근 업데이트 | 새 프로젝트 | 생성 성공 시 해당 프로젝트 음원 탭으로 이동. 빈 목록에는 생성 안내 표시 |
| 내 작업 | 전역 메뉴에서 담당 작업과 검토 대기 확인 | 내 담당 작업, 참여 프로젝트의 검토 대기, 마감 필터 | 작업 열기 | 항목을 누르면 해당 작업 상세가 열림 |
| 프로젝트 / 음원 | 프로젝트의 기본 화면 | 음원 이름, 최신 버전 파일명·업로드 시각·처리 상태 | 음원 업로드 | 행을 누르면 해당 음원의 최신 재생 가능 버전이 열림. 더 최신인 처리 중·실패 버전은 별도 상태 표시 |

| 프로젝트 / 작업 | 프로젝트 탭·피드백의 작업 연결에서 진입 | 기본 목록, 목록/보드 전환, 상태·담당자·마감 필터 | 새 작업 | 행이나 카드를 누르면 같은 작업 상세가 열림 |
| 작업 상세 | 목록·보드·내 작업·알림에서 진입 | 제목·설명, 연결 피드백, 상태·담당자·마감일 | 현재 상태에 맞는 진행·검토·완료 | 저장 후 상태와 관련 목록이 일치하고 원래 목록으로 돌아갈 수 있음 |
| 프로젝트 / 활동 | 활동 탭에서 진행 내역 확인 | 날짜별 업로드·피드백·작업 변경, 종류 필터 | 기록의 대상 열기 | 정확한 버전·피드백·작업으로 이동 |
| 프로젝트 / 설정 | 설정 탭에서 관리 | 팀원, 초대, 다운로드, 보관 관리 | 권한별 관리 동작 | 성공·실패와 변경 결과 표시. 보관·제거는 대상 확인 후 수행 |

음원 목록이 프로젝트의 출발점이며, 초기 작업 보기는 목록으로 제안한다. 보드는 같은 작업 데이터의 보기 전환으로 제공한다.

### 음원 상세 배치

```text
프로젝트 선택 ▾ / 새벽 EP
음원          작업          활동          설정
──────────────────────────────────────────────────────────────
음원 목록 / 메인 믹스           [버전 선택 ▾]  [수정본 업로드] [⋯]
mix-03.wav · 오늘 업로드 · 보컬 잔향 조정

재생·구간 선택 영역                       피드백
┌──────────────────────────────────┐     미해결 / 전체
│             파형과 피드백 표시      │     00:42 보컬이 조금 큼
└──────────────────────────────────┘     01:18 후렴 진입 확인
[재생] 00:42 / 03:24  음량
[현재 위치에 피드백] [구간 선택]           선택한 피드백과 답글
```

선택 버전은 파일명·업로드 시각·설명으로 구분한다. `v1`, `v2` 같은 버전 번호를 도입할 때는 서버의 안정된 순번을 사용한다. 좁은 화면에서는 플레이어 아래로 피드백을 배치하고 상세 입력은 전체 화면으로 연다.

## 3. 사용자가 수행하는 동작

### 첫 음원과 수정본 업로드

1. 음원 탭에서 `음원 업로드`를 누르거나 파일을 놓는다.
2. 한 파일을 선택하면 파일명으로 음원 이름을 제안한다. 이름은 편집할 수 있고 설명은 선택 입력이다.
3. 제출하면 음원 생성, 파일 전송, 버전 등록, 재생 준비를 상태별로 보여준다. 전송 완료 후에는 `재생 준비 중`으로 바뀐다.
4. 완료 시 새 버전 상세로 이동한다. 실패 시 입력과 확인된 음원·업로드 ID를 보존해 해당 단계부터 재시도한다.
5. 기존 음원에서는 `수정본 업로드`를 사용한다. 같은 음원에 새 버전을 연결하고 원래 피드백을 작성된 버전에서 계속 확인한다.

전송 중에는 작은 진행 표시를 유지한다. 업로드 요청은 앱 공통 레이아웃의 업로드 상태가 소유해 탭 이동 뒤에도 진행된다. 명시적인 취소와 브라우저 종료를 처리하며, 새로고침 후 전송 중 파일은 다시 선택하게 한다. 버전 등록만 남았다면 서버 상태를 조회해 중복 없이 완료한다. 생성 응답을 받지 못한 경우에는 기존 음원 확인 경로를 제공하고 생성 요청을 무조건 반복하지 않는다.

### 듣고 피드백 남기기

1. 음원을 열면 재생 버튼과 파형이 첫 화면에 들어온다.
2. 파형이나 키보드 탐색으로 위치를 고른 뒤 `현재 위치에 피드백`을 누른다. 그 순간의 밀리초 위치를 초안에 고정한다.
3. 입력 중 재생이 진행돼도 초안의 위치는 유지한다. 다른 버전으로 이동하려면 미저장 초안을 저장하거나 버리는 선택을 제공한다.
4. 구간 피드백은 `구간 선택`을 눌렀을 때 시작·끝 조작을 보여준다. 드래그와 키보드·시간 입력을 함께 지원한다.
5. 저장한 피드백을 누르면 해당 위치로 이동하며 선택한 대화의 답글 입력을 연다. 작성·수정·삭제·해결·다시 열기는 기존 권한을 적용한다.
6. `작업 만들기`를 누르면 피드백 내용과 원본 버전 링크가 채워진 작업 작성창을 연다. 생성 성공 후 작업 상세 링크를 제공한다.

파형의 피드백 표시는 목록과 같은 조회 결과를 사용한다. 겹치는 위치는 묶음과 개수로 표현하고, 키보드로 목록의 해당 피드백에 도달할 수 있게 한다. 미해결/전체 필터는 서버 전체 결과를 기준으로 적용한다.

### 수정 작업과 재검토

1. `새 작업`에서는 제목을 필수로 받고 설명·담당자·마감일을 선택 입력으로 둔다. 처음 상태는 `할 일`이다.
2. 작업 상세에서 상태를 `진행 중`으로 바꾸고 연결된 피드백을 확인한다.
3. 수정본 업로드 후 `검토 요청`을 누르면 결과 버전과 검토 설명을 받는다. 두 필드의 필수 조건은 기존 API 규칙을 따른다.
4. 검토자는 결과 버전을 열고 듣고 피드백을 남긴다. reviewer 역할의 상태 변경 권한은 기존 정책에 맞게 표시한다.
5. 권한이 있는 사용자가 `완료`를 누른다. 연결된 미해결 피드백이 있으면 해당 목록을 보여주고 명시적으로 확인받는다. 피드백의 해결 상태는 별도 동작으로 관리한다.

카드는 제목·담당자·마감일·연결 피드백 수만 간결하게 보여준다. 카드 제목이 상세 진입점이다. 보관·복원·순서 이동은 메뉴로 제공하고, 드래그와 키보드 이동 모두 같은 저장 경로를 사용한다. 검토·완료에 추가 입력이 필요한 이동은 해당 입력을 받은 뒤 확정한다.

## 4. 시각 기준과 상태별 동작

- GitHub의 콘텐츠 위계에 맞춰 본문은 행과 구분선 중심으로 구성한다. 흰색·연회색의 밝은 기본 화면, 한 가지 강조색, 명확한 활성 탭을 초기 시안으로 제안한다. 실제 대비와 선호는 사용성 확인에서 평가한다.
- 본문 글자는 14~16px, 페이지 제목은 22~24px를 기준으로 시작한다. 짧은 버튼과 입력 라벨에도 읽을 수 있는 크기를 유지한다. Geist와 한국어 시스템 글꼴을 사용한다.
- 화면의 대표 행동만 강조한다. 파일 목록에서는 업로드, 피드백 입력에서는 저장, 작업 작성에서는 만들기가 해당한다. 보관·삭제는 추가 메뉴와 확인 창에서 제공한다.
- 사용자에게는 `피드백`, `작업`, `수정본 업로드`, `다운로드`를 사용한다. `Note`, `Task`, `MediaVersion`은 API·코드의 기존 식별자로 관리한다.
- 모바일은 프로젝트 선택기를 접고 현재 프로젝트와 탭을 먼저 보여준다. 390px 폭에서 페이지 전체의 가로 스크롤을 없애고, 보드의 가로 스크롤은 보드 영역 안에서 처리한다. 목록 보기로도 모든 작업에 접근할 수 있어야 한다.
- 상세 폼은 접근 가능한 대화상자 또는 상세 페이지로 구현한다. Escape 닫기, 포커스 이동·복귀, 미저장 입력 처리를 적용한다. 읽기 화면은 브라우저 뒤로 가기로 이전 목록과 필터에 돌아온다.

| 상태 | 화면에서 제공할 동작 |
| --- | --- |
| 첫 프로젝트·첫 음원·첫 피드백 없음 | 대상에 맞는 짧은 안내와 한 가지 시작 행동 |
| 필터 결과 없음 | 현재 필터를 보여주고 초기화 제공 |
| 로딩 | 예정된 콘텐츠 자리에서 진행 상태 표시. 이전 프로젝트 내용과 섞지 않음 |
| 업로드·처리 중 | 전송률과 처리 상태 구분. 허용된 취소·재시도 제공 |

## 5. 라우팅과 API 구현 계약

### 공유·복원할 URL

| 목적 | 제안 경로 |
| --- | --- |
| 프로젝트 목록 | `/projects` |
| 내 작업 | `/work?filter=assigned` 또는 `review`·`due`·`late` |
| 프로젝트 음원 | `/projects/:projectId/media` |
| 특정 버전 검토 | `/projects/:projectId/media/:itemId/versions/:versionId?note=:noteId&at=:milliseconds` |
| 작업 목록·보드 | `/projects/:projectId/tasks?view=list` 또는 `board`, 상태·담당자 필터 |
| 작업 상세 | `/projects/:projectId/tasks/:taskId` |
| 활동·설정 | `/projects/:projectId/activity`, `/projects/:projectId/settings` |

새로고침·뒤로 가기·앞으로 가기에서 프로젝트, 선택 버전, 피드백, 작업과 필터를 복원한다. 작업 상세의 목록 복귀에는 현재 프로젝트의 검증된 필터 쿼리만 전달한다. 로그인 복귀 경로는 허용된 앱 상대 경로와 파라미터를 검증한다.

기존 `/?project=...&version=...&note=...&at=...`, `task_note=...`, `#task-board`는 새 경로로 변환한다. 버전 상세 조회에서 item ID를 확인해 이동하고, `task_note`는 피드백이 연결된 작업 작성으로 이어진다. 해시는 클라이언트에서 읽어 변환한다. 로그인 전에도 원래 대상을 보존한다.

### 현재 계약과 필요한 변경

| 기능 | 코드에서 확인한 현재 계약 | 구현할 범위 | 담당 PR |

계약을 바꾸는 PR에서 OpenAPI와 생성 타입을 같이 갱신한다. 기존 응답의 배열 구조는 유지하면서 필요한 필드를 추가하고, 별도 집계는 해당 목록 조건을 공유한다. 권한 검사는 단건 조회와 집계에도 적용한다. 전체 검색 결과를 첫 100개 클라이언트 필터로 대신하지 않는다.

피드백 저장은 버전 ID와 정수 밀리초를 받는다. 초안은 작성 시작 시의 위치를 소유하고, 플레이어는 현재 재생 위치를 소유한다. 화면별 요청은 이탈·대상 변경 시 정리한다. 저장 성공 후 관련 목록·개수·활동을 재조회하고, 실패 시 초안을 유지한다.

## 7. 수용 기준과 검증 기록

### 화면별 기준

- 1440×900에서 프로젝트 이름·활성 탭·주요 행동을 첫 화면에서 확인한다. 음원 상세 진입 후 재생 버튼과 파형이 보인다.
- 프로젝트·음원·작업·알림 링크를 새 탭에서 열어 같은 대상을 확인한다. 로그인 후에도 대상 버전·피드백·작업이 보존된다.
- 입력창이 열린 동안 Escape·뒤로 가기·탭 이동·버전 변경의 결과가 일관되며, 미저장 입력을 처리할 수 있다.
- 390×844에서 페이지 가로 잘림이 없고, 터치·키보드로 업로드·피드백·작업 확인에 접근한다. 버튼의 터치 영역은 44px를 기준으로 확보한다.
- 표시된 검색·필터·개수는 전체 접근 가능한 결과와 일치한다. 100개 초과 목록과 오래된 직접 링크를 확인한다.
- `할 일 → 진행 중 → 검토 요청 → 완료`, 피드백의 해결·다시 열기, 보관·복원과 권한 철회를 기존 API 규칙으로 검증한다.

### 두 계정 시나리오

1. 소유자가 프로젝트를 만들고 WAV를 업로드한다.
2. 초대받은 사용자가 링크에서 해당 버전을 열어 특정 시간에 피드백을 남긴다.
3. 소유자가 피드백에서 작업을 만들고 담당자를 지정한다.
4. 담당자가 작업 링크에서 맥락을 확인하고 MP3 수정본을 올려 검토를 요청한다.
5. 검토 후 권한이 있는 사용자가 작업을 완료한다. v1 피드백은 원래 버전에서 확인한다.
6. 활동·알림에서 같은 대상을 다시 열고, 내 작업과 보드의 상태를 비교한다.

처음 사용하는 사람에게 위 흐름을 설명 없이 수행하게 하고, 첫 클릭 위치, 잘못 들어간 화면, 도움을 요청한 구간, 완료 여부를 기록한다. 이 항목은 예정된 사용성 검증이며 현재 개선 효과를 측정한 결과는 없다.

현재는 기존 화면의 데스크톱·모바일 배치, 작업 작성 폼, URL이 갱신되지 않는 프로젝트 선택을 Chrome에서 확인했다. 새 UI의 동작과 사용성은 후속 구현 후 검증한다.

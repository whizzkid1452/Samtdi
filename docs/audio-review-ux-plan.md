# 사맛디 음원 리뷰 UX 개선 플랜

작성일: 2026년 11월 13일. 상태: **구현 및 로컬 검증 완료**.

음원을 열면 바로 듣고, 같은 화면에서 위치를 지정해 피드백을 남기고, 수정본을 다시 확인할 수 있게 한다. Samply의 음원·버전 중심 탐색과 Frame.io의 미디어 옆 피드백 흐름을 참고한다.

조사 기준은 로컬 `codex/web-waveform-seeking`의 `bda86bac3def145960524604e61af8ef57abd337`과 실행 중인 음원 상세 화면이다. `origin/main`에 모두 반영된 상태라는 뜻은 아니다. [기존 UI 계획](web-ui-redesign-plan.md)의 UI-01~06 이후 작업이며, [파형 탐색 PR #22](https://github.com/whizzkid1452/Samtdi/pull/22)의 동작을 유지한다. 구현 착수 전에 main과 선행 PR 상태를 다시 확인한다.

이 문서는 화면, 조작 규칙, 구현 범위와 PR 완료 조건을 관리한다. **설계 판단과 이유 표, 상태·구조도는 [사맛디 Notion](https://app.notion.com/41673b56612a814884cdef5a60bd96d8)에만 기록한다.**

## 3. 목표 화면

### 데스크톱

기존 프로젝트 탭 아래에서 상단의 중복 정보를 줄인다. 넓은 화면은 파형 약 2/3, 피드백 약 1/3로 시작하고 피드백 폭은 읽을 수 있는 최소 너비를 확보한다. 800px 이하에서는 세로 배치한다.

| 위치 | 표시할 내용 | 기본 행동 |
| --- | --- | --- |
| 상단 한 묶음 | 음원 목록 복귀, 곡 제목, 선택 파일명·날짜, 최신/이전 버전 표시 | 버전 선택, 보조 버튼 `수정본 업로드`, 관리 메뉴 |
| 왼쪽 상단 | 큰 파형, 시간 눈금, 플레이헤드, 피드백 마커 | 클릭·가로 드래그로 재생 위치 이동 |
| 파형 바로 아래 | 재생/일시정지, 현재/전체 시간, 음량 | 재생 버튼을 가장 쉽게 찾게 배치. 별도 탐색 슬라이더 없음 |
| 파형 보조 도구 | `구간 지정`, 선택한 시작·끝, `구간 듣기`, `해제` | 기본 탐색과 구간 지정을 명시적으로 전환 |
| 오른쪽 상단 | 피드백, 전체/미해결/해결됨, 시간순/최신순 | 기본값은 전체·시간순 |
| 오른쪽 본문 | 작성자, 위치, 본문 2줄, 답글 수, 해결 상태 | 댓글 선택 시 해당 카드 안에 대화 펼치기 |
| 오른쪽 작성 영역 | `이 위치에 피드백 남기기`, 고정된 시점 또는 구간 | 모달 없이 입력·저장. 편집 중에만 저장 버튼 강조 |

새 피드백과 답글의 편집 영역은 동시에 펼치지 않는다. 선택한 대화에서 `답글`을 누르면 해당 카드에 입력을 열고 새 피드백 작성 영역은 접는다. `새 피드백`을 누르면 패널의 작성 영역으로 전환한다. 작성 중인 내용은 대상별로 보관한다.

밝은 배경과 기존 사맛디 강조색을 유지한다. 카드 안의 중첩 테두리와 반복 라벨을 줄이고 제목·시점·본문·보조 행동의 순서를 통일한다. 색 외에도 선택·해결 상태를 텍스트와 아이콘으로 표시한다.

### 모바일

- 곡·버전 → 재생·파형 → 피드백 순서로 배치한다. 페이지 전체의 가로 스크롤은 만들지 않는다.
- 본문을 스크롤해도 재생/일시정지와 현재 시각에 접근할 수 있는 작은 재생 조작부를 유지한다. 가상 키보드가 열리면 입력과 저장 버튼을 가리지 않게 배치한다.
- 작성은 피드백 영역에서 이어간다. 초점 이동 시 작성 중인 위치·구간 라벨도 함께 보이게 한다.
- 기본 파형의 가로 드래그는 탐색, 세로 이동은 페이지 스크롤이다. 구간 지정 모드에서만 구간 제스처를 사용한다. 44px 터치 영역과 숫자 입력 대안을 제공한다.

## 4. 조작 규칙

### 듣기와 위치 이동

1. 음원 목록에서 진입하면 가장 최근 재생 가능한 버전을 연다. 자동 재생하지 않는다. 최신 수정본이 처리 중이면 현재 재생 가능한 파일과 처리 상태를 구분한다.
2. 파형 클릭·기본 드래그는 위치 이동이다. 구간 선택이나 피드백 작성으로 해석하지 않는다.
3. 댓글을 누르면 대화를 펼치고 해당 시작 위치로 이동한다. 정지 중이면 정지를 유지하고 재생 중이면 이어 듣는다. 구간 댓글은 해당 영역을 함께 강조한다.
4. 파형 키보드 탐색을 유지한다. Space 재생/일시정지는 플레이어 영역에 초점이 있을 때만 적용하고 텍스트 입력·버튼 기본 동작을 가로채지 않는다.
5. 버전·페이지가 바뀌면 이전 재생·프레임 갱신·요청을 정리한다. 버전 전환은 새 파일의 0초·정지 상태로 시작하며, 정확한 위치를 포함한 직접 링크는 링크의 위치를 우선한다.

### 시점 피드백과 답글

1. `이 위치에 피드백 남기기`를 누르거나 비어 있는 작성 영역에 처음 진입한 시점에 버전과 실제 오디오 시간을 초안에 고정한다. 기존 초안 복원은 위치를 다시 잡지 않는다.
2. 작성 진입 시 재생 중이면 일시정지한다. 사용자가 다시 재생해도 초안 위치는 고정하며 저장 후에는 자동 재생하지 않는다.
3. 입력 위에 `0:42.300에 남기는 피드백` 또는 `0:42.300~0:47.100 구간 피드백`을 표시한다. `현재 위치로 변경`은 명시적으로 누른 경우에만 초안 위치를 갱신한다.
4. Enter는 줄바꿈, Cmd/Ctrl+Enter는 저장이다. 한국어 조합 중에는 단축키로 저장하지 않는다. 빈 본문·중복 클릭을 차단하고 저장 중·실패를 입력 옆에 표시한다.
5. 저장 성공 후 해당 댓글을 선택하고 파형 마커·목록을 갱신한다. 초안은 성공이 확인된 뒤에만 지운다. 생성 결과를 확인하지 못한 요청을 자동 재전송하지 않는다.
6. 마커 묶음을 누르면 그 위치의 댓글 후보를 보여주고 사용자가 하나를 선택한다. 같은 숫자 버튼을 반복해서 눌러 숨은 대화를 순환하는 동작을 교체한다.
7. 댓글 선택·필터·버전 변경 시 새 피드백과 답글 초안을 각 계정·버전·댓글 기준으로 보관하고 돌아오면 복원한다. `초안 버리기`는 별도 행동이다. sessionStorage를 사용할 수 없으면 보관 불가를 알리고 미저장 입력이 있는 화면 이탈을 확인한다.
8. 직접 링크의 댓글이 현재 필터나 첫 페이지에 없어도 단건 조회로 열고 `현재 목록 밖의 피드백`을 표시한다. 링크를 누를 때 필터를 몰래 바꾸지 않는다.

초안은 같은 탭의 세션 범위에서 보관한다. 다른 기기·브라우저로 이어지는 서버 초안 저장은 이번 범위에 포함하지 않는다. 답글 선택 전환, 편집 취소, 브라우저 뒤로 가기에서도 위 규칙을 적용한다.

### 구간 지정과 재청취

1. `구간 지정`을 누르면 모드 안내와 시작·끝 조작을 보여준다. 이 모드에서 드래그하면 범위를 선택하고, 일반 탐색으로 돌아가려면 `해제` 또는 Escape를 누른다.
2. 선택 후 양 끝 손잡이와 시간 입력으로 범위를 조정한다. 파형 좌표와 시간 입력은 같은 범위를 수정한다. 길이가 0이거나 끝이 시작보다 앞서면 구간 작성·재생을 활성화하지 않는다.
3. `구간에 피드백`은 해당 범위를 고정한 초안을 오른쪽에 연다. 이후 선택 범위를 바꿔도 작성 중인 초안에 자동 반영하지 않는다.
4. `구간 듣기`는 시작점으로 이동해 한 번 재생하고 끝에서 멈춘다. 반복 재생은 이번 범위에 넣지 않는다.
5. 선택된 구간 댓글의 `구간 듣기`도 같은 동작을 사용한다. 일반 탐색·다른 댓글 선택·버전 전환은 구간 재생을 끝낸다. 댓글 선택만으로 구간 재생을 시작하지 않는다.
6. 저장·선택 취소 후 기본 탐색 모드로 돌아간다. 저장된 댓글의 강조 범위와 새로 고르는 범위를 구분한다.

### 버전과 수정 작업

- 버전 선택기 안에서 파일명·업로드 시각·설명·준비 상태를 보여준다. 목록 일부의 배열 인덱스로 `v1/v2` 번호를 만들지 않는다. 현재 계약에서 제공하지 않는 업로더 표시도 추가하지 않는다.
- 현재 선택 파일의 정보를 상단 한 번만 표시한다. 이전 파일에는 `이전 버전 검토 중`과 `최신 재생 가능 버전 열기`를 제공한다. 최신 파일이 처리 중이면 별도로 안내한다.
- 새 버전 업로드 중 현재 리뷰를 유지한다. 준비 완료 후 사용자가 선택해 이동하며 자동으로 댓글·초안을 새 버전으로 옮기지 않는다.
- `작업 만들기`는 리뷰 화면 위에서 기존 TaskEditor를 연다. 제목·노트·원본 버전을 채우고 닫으면 같은 댓글로 돌아온다. 작성 성공 후 연결된 작업을 다시 조회하고 작업 상세 링크를 보여준다.
- 이미 연결된 작업이 있으면 제목·상태·링크를 먼저 보여준다. 사용자가 선택하면 추가 작업도 만들 수 있다. 노트당 작업 하나라는 새 제약은 도입하지 않는다.
- 해결/다시 열기와 작업 완료는 별개다. 검토자는 기존 권한대로 본인 피드백을 관리하고, 작업 생성은 소유자·편집자에게 제공한다. 보관된 음원에서는 작성 동작을 숨기고 읽기 상태를 표시한다.

## 5. 구현 대상과 조회 계약

기존 Next.js·Go·HTMLAudioElement를 사용한다. 파형 라이브러리, 전역 상태 라이브러리, WebSocket은 새로 도입하지 않는다. 아래 분리는 해당 기능을 구현하면서 필요한 범위에서 수행한다.

### 노트 조회

- 응답 배열 구조와 기존 `before` 동작은 보존한다. 새 UI는 `sort=time|recent`, `filter=open|resolved` 또는 필터 생략, 새 `after` 커서를 사용한다. 정렬 생략은 기존 작성순이다.
- 시간순은 `(start_ms, id)` 오름차순, 최신순은 `(created_at, id)` 내림차순이다. `after`는 해당 정렬에서 마지막으로 받은 노트 ID를 기준으로 다음 페이지를 요청한다. `before`는 기존 최신순 조회에서만 허용하며 시간순과 조합하거나 `after`와 동시에 보내면 거절한다.
- 필터·정렬 변경 시 커서를 초기화하고 이전 요청을 취소한다. 커서·직접 노트·작업 필터 모두 프로젝트·버전 권한과 소속을 검증한다.
- 목록 첫 100개만 클라이언트에서 정렬해 전체 시간순처럼 표시하지 않는다. 필요한 DB 인덱스는 실제 쿼리 계획을 확인해 같은 PR에서 추가한다.
- 마커는 같은 필터로 불러온 노트 범위를 나타낸다. 다음 페이지가 있으면 `불러온 피드백 100개 표시 · 더 보기`처럼 부분 결과임을 알린다. 총합처럼 보이는 숫자를 만들지 않는다. 버전 전체 마커 집계는 후속으로 둔다.
- 필터에서 빠진 선택 댓글은 명시적인 별도 카드로 유지한다. 서버 변경 후 조회를 갱신하되 선택·입력·포커스를 불필요하게 초기화하지 않는다.

### 작업 조회와 주소

- `/v1/projects/:project/tasks?note=:noteId`에 연결 노트 조건을 추가한다. 기존 작업 페이지네이션·역할 검사를 유지하고 집계에도 같은 필터 조건을 반영한다. 모든 작업을 내려받아 화면에서 찾지 않는다.
- 버전·피드백 URL은 기존 경로와 `note`, `at` 의미를 유지한다. 공유 링크는 특정 버전을 가리키며 최신 버전으로 자동 전환하지 않는다.
- 필터·정렬은 URL의 `feedback=all|open|resolved`, `sort=time|recent`로 보존한다. 생략 시 전체·시간순이며 route 파서·링크 생성·로그인 복귀 검증을 같은 PR에서 갱신한다. 재생 프레임마다 URL을 갱신하지 않는다.

## 7. 수용 기준과 검증

### 사용성 관찰

처음 보는 사용자가 안내 없이 아래 과업을 수행하는지 관찰한다. 사용자가 찾지 못한 버튼, 모드 혼동, 댓글을 잃었다고 느끼는 순간을 기록해 해당 단계에서 수정한다. 성공률·소요 시간은 실제 관찰 전에는 성과로 쓰지 않는다.

1. 음원 목록에서 곡을 열고 재생한다.
2. 원하는 위치로 이동해 시점 피드백을 남긴다.
3. 구간을 지정해 듣고 구간 피드백을 남긴다.
4. 기존 피드백을 눌러 해당 부분을 듣고 답글을 작성한다.
5. 미해결만 확인하고 하나를 해결한 뒤 다시 찾는다.
6. 수정본을 열고 현재 버전을 구분하며 원래 버전의 피드백으로 돌아간다.
7. 피드백을 작업으로 연결하고 리뷰 화면으로 돌아온다.

### 기능·접근성 회귀

- 재생 위치의 원본은 실제 오디오 시간이다. 재생·정지·탐색·종료·버전 변경 뒤 플레이헤드를 확인하며 제거한 초록색 탐색 바가 다시 생기지 않는다.
- 입력 실패·충돌·필터·선택·뒤로 가기·새로고침·버전 전환에서 새 피드백과 답글 초안을 확인한다. 초안의 버전·위치가 바뀌거나 다른 계정에 표시되지 않는다.
- 각 입력의 저장 상태와 읽기 전용 사유를 표시한다. 편집 중 재조회가 내 본문을 덮지 않는다. 자동 저장·자동 재전송·자동 해결을 암시하지 않는다.
- 파형·마커·구간 손잡이·카드·편집기에 키보드로 접근하고 포커스가 보인다. 터치와 시간 입력으로도 같은 동작을 수행한다. 화면 낭독기에 재생 시간을 매 프레임 알리지 않는다.
- 로딩, 빈 목록, 필터 결과 없음, 처리 중·실패 버전, 삭제 댓글, 접근 권한 없음, 네트워크 실패를 각 영역에서 확인한다.
- Chrome·Firefox와 모바일 크기 WebKit에서 검증하고, 실제 iOS/Android의 터치·키보드는 별도로 기록한다. 에뮬레이션을 실기기 검증으로 표시하지 않는다.

구현 시 `apps/web`의 `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm verify:pilot`을 실행한다. API 변경 PR은 격리 DB의 `ops/verify-web.sh`와 해당 Go 검사를 포함한다. 저장소에는 별도 웹 단위 테스트 명령이 현재 없으므로 파형·초안·조회 변경에 필요한 검증을 기존 브라우저 시나리오와 API 검사에 추가한다. 프로젝트 데이터에 영향을 주는 검사는 격리된 검증 프로젝트·DB를 사용한다.

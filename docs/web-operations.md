# 사맛디 운영과 복원

웹 릴리스는 한 호스트에서 Go API, Next.js, FFmpeg 작업자를 별도 프로세스로 실행합니다. `ops/systemd`의 예시와 `ops/Caddyfile.example`을 사용해 Go와 Next.js를 루프백에 두고 외부의 같은 HTTPS 출처를 연결합니다. 스토리지·DB·OIDC는 운영 환경에서 제공하는 서비스를 사용합니다.

## 릴리스

1. 릴리스 커밋을 체크아웃합니다. Go 1.25와 Node.js 22 이상, pnpm 10.15, FFmpeg·FFprobe를 준비합니다. `apps/web`에서 `pnpm install --frozen-lockfile`과 `pnpm build`, `services/collaboration`에서 `go build -o ../../bin/ayotbi-collaboration ./cmd/ayotbi-collaboration`을 실행합니다.
2. 서비스 계정 `samtdi`가 새 릴리스 디렉터리를 읽게 합니다. 운영 설정은 접근 권한을 제한한 `/etc/samtdi/api.env`에 주입합니다. `AYOTBI_ORIGIN`은 실제 HTTPS 출처, `AYOTBI_OIDC_ISSUER`는 운영 발급자이며 콜백은 외부 출처의 `/v1/auth/callback`입니다. 운영에서는 `AYOTBI_ALLOW_LOOPBACK_HTTP`를 설정하지 않습니다.
3. 객체 버킷은 비공개로 두고 브라우저의 임시 업로드 PUT만 실제 웹 출처의 CORS에 허용합니다. 서명 키의 범위, API·작업자·운영자별 스토리지 권한과 보관 기간을 배포 시 기록합니다. 예시 도메인과 로컬 OIDC 계정은 개발용입니다.
4. 쓰기 중단 동안 백업을 만들고 새 릴리스로 `/opt/samtdi/current`를 전환합니다. API를 시작해 `/readyz`를 확인한 뒤 작업자와 웹을 시작합니다. 운영 계정으로 로그인과 새 Range 재생, 업로드 처리를 확인합니다.

이전 바이너리로 돌아갈 때 운영을 중지하고 스키마 호환이 확인된 이전 릴리스를 선택합니다. 추가 마이그레이션이 비호환이면 새 데이터의 보관 범위를 정한 뒤 격리 환경에서 사전 백업을 복원합니다. 운영 DB에 삭제 마이그레이션을 자동 적용하지 않습니다.

## 백업과 복원

API와 작업자를 모두 종료하고 열려 있던 임시 업로드 승인의 만료를 기다립니다. 승인 유효 기간은 최대 15분입니다. 백업 명령은 API 또는 작업자가 사용하는 공동 DB 잠금과 충돌하면 거절합니다. 백업 도중에는 API·작업자를 다시 실행하지 않습니다.

운영 환경을 적용한 상태에서 다음 명령을 사용합니다.

```sh
./bin/ayotbi-collaboration snapshot /secure-backups/samtdi-20261112
```

현재 백업 형식 3은 계정 연결, 작업실, 협업 데이터, 확정 원본·재생본·파형, 처리 대기 원본을 보관합니다. 객체는 바이트 수와 SHA-256으로 검증합니다. 기존 Git 데이터를 포함한 배포는 Git 설정을 사용합니다. 웹 전용 배포는 Git 설정 없이 실행합니다. 형식 1·2와 이전 스키마의 형식 3 백업도 복원할 수 있습니다.

복원은 별도 빈 DB와 전용 비공개 버킷을 지정합니다.

```sh
./bin/ayotbi-collaboration restore /secure-backups/samtdi-20261112
```

매니페스트와 테이블·객체 해시를 검증한 뒤 데이터를 복원합니다. 기존 계정·프로젝트가 있는 DB는 거절합니다. 진행 중이었던 작업은 새 임대를 받고 로그인 세션과 미완료 초대 토큰은 재사용하지 않습니다. 새로 로그인해 이전 버전의 WAV 재생과 탐색, L/R 파형, 게시 출처, 노트·카드·활동·알림을 확인한 뒤 새 출처를 사용합니다. 복원에 걸린 시간, 백업 커밋, 버킷과 DB 대상 식별자를 기록합니다.

## 운영 관측

운영자만 `/v1/operations`를 조회할 수 있습니다. API별 요청·오류·응답 바이트, 웹 미디어 상태별 개수·확정 객체 바이트·가장 오래된 미완료 작업을 확인합니다. API 카운터는 프로세스 재시작 때 초기화되므로 운영 수집기에서 시간 구간으로 집계합니다. 직접 업로드 트래픽은 객체 저장소 지표에서 봅니다. 서명 URL·세션·노트 본문은 로그 수집에서 제외합니다.

## 기존 음원의 채널별 파형 생성

신규 음원은 채널별 파형을 생성합니다. 기존 모노 파형은 계속 표시됩니다. 운영 점검 시간에 API와 미디어 작업자를 정상 종료한 뒤 같은 DB·S3 설정으로 `ayotbi-collaboration rebuild-waveforms`를 실행하면 저장된 재생본에서 파형을 다시 만듭니다. 재생본·음원 버전 ID·피드백은 그대로 사용합니다. 이미 갱신한 버전은 재실행 시 건너뜁니다.
